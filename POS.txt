เอกสารกำหนดความต้องการของระบบ (Software Requirements Specification)

ชื่อโครงการ: ระบบบริหารจัดการร้านอาหาร ณ จุดขาย (Restaurant POS System)

1. วัตถุประสงค์ (Objective)

เพื่อพัฒนาระบบ Point of Sale (POS) สำหรับร้านอาหารที่ช่วยอำนวยความสะดวกในการบริหารจัดการงานหน้าร้าน การรับออเดอร์ การจัดการโต๊ะ การจัดการข้อมูลการจอง ตลอดจนการจัดการข้อมูลหลังบ้าน เช่น บัญชีรายรับ-รายจ่าย เพื่อให้ใช้งานง่ายภายในระบบเดียว

2. กลุ่มผู้ใช้งานระบบ (User Roles)

ระบบนี้ถูกออกแบบมาสำหรับการใช้งานแบบ Single Role ผู้ใช้งานทุกคนมีสิทธิ์เข้าถึงฟังก์ชันทั้งหมดของระบบ ได้แก่

พนักงาน/ผู้จัดการ (Staff/Manager): มีสิทธิ์ในการรับออเดอร์ จัดการสถานะและข้อมูลการจองโต๊ะ ทำรายการรับชำระเงิน และดูหรือจัดการข้อมูลบัญชีรายรับ-รายจ่าย

3. ความต้องการทางฟังก์ชัน (Functional Requirements)

ส่วนนี้คือฟังก์ชันที่ระบบ "ต้องทำได้" เพื่อตอบสนองความต้องการทางธุรกิจ

3.1 ระบบการจัดการสิทธิ์ผู้ใช้งาน (User Management)

REQ-1.1: ระบบมีหน้าจอเข้าสู่ระบบ (Login) ด้วย PIN (หรือ Username/Password) เพื่อความปลอดภัยขั้นพื้นฐาน

REQ-1.2: ผู้ใช้งานที่เข้าสู่ระบบสำเร็จ จะสามารถเข้าถึงฟังก์ชันทุกส่วนของระบบได้ (Dashboard, POS, Tables, Accounting)

3.2 ระบบการจัดการโต๊ะและการจองในร้านอาหาร (Table & Reservation Management)

REQ-2.1: ระบบต้องแสดงผังโต๊ะ (Table Layout) หรือรายการโต๊ะทั้งหมดในร้านได้

REQ-2.2: ระบบต้องแสดงสถานะของโต๊ะด้วยสีหรือสัญลักษณ์ที่ชัดเจน ได้แก่:

ว่าง (Available): โต๊ะพร้อมให้บริการ (เช่น สีเขียว)

กำลังใช้งาน (Occupied): มีลูกค้านั่งอยู่และกำลังทานอาหาร (เช่น สีแดง)

ถูกจองแล้ว (Reserved): โต๊ะถูกจองไว้ล่วงหน้า (เช่น สีเหลือง)

REQ-2.3: พนักงานต้องสามารถคลิกเพื่อเปลี่ยนสถานะโต๊ะ เปิดบิลโต๊ะ หรือรับออเดอร์เข้าโต๊ะนั้นๆ ได้

REQ-2.4: เมื่อเปลี่ยนสถานะโต๊ะจาก "ว่าง" เป็น "ถูกจองแล้ว" ระบบต้องบังคับให้พนักงานกรอกข้อมูลการจอง ได้แก่ ชื่อลูกค้า และ เบอร์โทรศัพท์

REQ-2.5: ระบบต้องแสดงข้อมูลชื่อลูกค้าและเบอร์โทรศัพท์ที่จองไว้ เมื่อพนักงานเรียกดูข้อมูลของโต๊ะที่มีสถานะ "ถูกจองแล้ว"

3.3 ระบบบัญชีรายรับและรายจ่าย (Accounting & Financial Management)

REQ-3.1: ระบบต้องบันทึกยอดขาย (รายรับ) จากระบบ POS เข้าสู่ระบบบัญชีโดยอัตโนมัติเมื่อมีการชำระเงินเสร็จสิ้น

REQ-3.2: ระบบต้องมีหน้าต่างให้พนักงานสามารถบันทึก "รายจ่าย" เพิ่มเติมได้ (เช่น ค่าวัตถุดิบ, ค่าเช่าที่, ค่าน้ำค่าไฟ, ค่าจ้างพนักงาน) พร้อมระบุวันที่และหมวดหมู่

REQ-3.3: ระบบต้องมี Dashboard สรุปข้อมูลทางการเงินแบบเข้าใจง่าย ประกอบด้วย:

ยอดรวมรายรับ (Total Revenue)

ยอดรวมรายจ่าย (Total Expenses)

กำไรสุทธิ (Net Profit)

REQ-3.4: ระบบต้องสามารถกรอง (Filter) ดูรายงานรายรับ-รายจ่าย รายวัน, รายสัปดาห์, รายเดือน และรายปีได้

3.4 ระบบการขายหน้าร้าน (POS & Order Management)

$$ส่วนที่จำเป็นต้องมีเพื่อให้ระบบทำงานได้$$

REQ-4.1: ระบบต้องมีหน้าจอแสดงรายการอาหาร แบ่งตามหมวดหมู่ (เช่น อาหารคาว, เครื่องดื่ม, ของหวาน)

REQ-4.2: พนักงานสามารถกดเลือกรายการอาหารลงในตะกร้า (Cart) และระบุโต๊ะที่สั่งได้

REQ-4.3: ระบบต้องคำนวณยอดรวมสุทธิ (Subtotal), ภาษี (VAT), และส่วนลด (Discount) ได้อัตโนมัติ

REQ-4.4: ระบบต้องรองรับการรับชำระเงินและเปลี่ยนสถานะโต๊ะกลับเป็น "ว่าง (Available)" เมื่อชำระเงินเสร็จสิ้น

4. ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements)

NFR-1 ความปลอดภัย (Security): ข้อมูลทางบัญชีต้องถูกป้องกันด้วยการเข้าสู่ระบบ

NFR-2 การรองรับอุปกรณ์ (Responsiveness): หน้าจอ POS ต้องออกแบบมาให้รองรับการใช้งานบนหน้าจอสัมผัส (Touch Screen) เช่น Tablet (iPad/Android) และหน้าจอคอมพิวเตอร์ทั่วไปได้

NFR-3 ความรวดเร็ว (Performance): การอัปเดตสถานะโต๊ะและการบันทึกข้อมูลการจองควรเกิดขึ้นอย่างรวดเร็ว (Near Real-time)

5. เทคโนโลยีที่ใช้ในการพัฒนา (Technology Stack)

เพื่อรองรับการทำงานของระบบ POS และการจัดการข้อมูลแบบ Real-time ขอเสนอโครงสร้างเทคโนโลยี (Tech Stack) เบื้องต้นดังนี้:

Frontend (ส่วนแสดงผลสำหรับผู้ใช้งาน):

shadcn/ui: ชุด UI Components คุณภาพสูง (เช่น ปุ่ม, ฟอร์ม, โมดอล, ตาราง) ที่นำมาใช้ประกอบเป็นหน้าจอ POS ช่วยให้ระบบมีหน้าตาที่ทันสมัย สะอาดตา ใช้งานง่าย และลดระยะเวลาในการพัฒนา

Backend (ส่วนจัดการ API และตรรกะของระบบ):

node.js ร่วมกับ Express.js: เพื่อจัดการการทำงานเบื้องหลัง เช่น การคำนวณยอดเงิน การบันทึกบิล การดึงข้อมูลการจองโต๊ะ และการเชื่อมต่อกับฐานข้อมูล

Database (ฐานข้อมูล):

PostgreSQL หรือ MySQL: ฐานข้อมูลเชิงสัมพันธ์ (Relational Database) ซึ่งเหมาะสมอย่างยิ่งกับการเก็บข้อมูลทางการเงิน (บัญชี) ข้อมูลออเดอร์ และการจัดการคลังข้อมูลที่มีความซับซ้อน ช่วยป้องกันข้อมูลสูญหายหรือผิดพลาด

Security & Authentication (ระบบรักษาความปลอดภัย):

JWT (JSON Web Token): ใช้สำหรับการยืนยันตัวตนและการจัดการ Session เมื่อผู้ใช้เข้าสู่ระบบด้วย PIN
